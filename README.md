# DriveNet: From Imitation to Autonomy

An end-to-end autonomous driving system built on CARLA 0.9.16. The project
progresses through five stages: collecting expert driving data across diverse
conditions, training a condition-aware convolutional policy via behavior cloning,
refining that policy with Proximal Policy Optimization through live simulator
interaction, benchmarking across scenarios, and estimating causal effects of
driving conditions on performance via propensity score matching.

The driving agent receives a front-facing RGB camera image and vehicle state
(speed, heading) as input and outputs continuous controls (steering, throttle,
brake).

## Prerequisites

- Windows 11 with an NVIDIA GPU (tested on RTX 5080, 32 GB system RAM)
- CARLA 0.9.16 simulator installed at `CARLA_0.9.16/`
- Python 3.11 with CUDA 12.8 support
- All Python dependencies listed in `requirements.txt`

## Configuration

All hyperparameters are defined in `configs/*.yaml`. Agents and notebooks load
parameters from these files via `src.config.load_config()`. To change a
hyperparameter, edit the YAML file -- both agents and notebooks read from the
same source.

## Notebook Pipeline

1. **Data Collection** -- Connect to CARLA and collect ~97,200 expert driving
   frames across 324 conditions (6 weather presets x 6 towns x 3 times of day x
   3 traffic densities). Each condition gets 300 frames at 20 FPS. Data includes
   camera images, vehicle state, expert actions, and metadata labels.

2. **Behavior Cloning** -- Train BC_model, a condition-aware DriveNet that takes
   camera images, vehicle state, and metadata embeddings (weather, town, road type,
   time of day, traffic) to predict steering, throttle, and brake. Trained on all
   6 towns with GPU augmentation. Saved as `models/BC_model_best.pt`.

3. **PPO Fine-Tuning** -- Initialize from BC_model weights and fine-tune through
   online CARLA interaction. A two-phase curriculum starts on ClearNoon (steps
   0--50k) then expands to all 6 weather presets. Supports three driving styles
   (see below). Per-town, per-style checkpoints: `models/ppo_{town}_{style}_best.pt`.

4. **Evaluation** -- Benchmark BC_model and all PPO style variants across 3
   weather conditions and 3 episodes per condition per town. Metrics: route
   completion, collision rate, lane-keeping fraction, average speed, and survival
   steps. Statistical significance via Mann-Whitney U test.

5. **Causal Analysis** -- Estimate causal effects of driving conditions (rain,
   night, urban terrain, PPO vs BC, driving style) on model performance using
   propensity score matching. Reports average treatment effects with bootstrap
   confidence intervals and Rosenbaum sensitivity bounds.

## Driving Styles

PPO fine-tuning supports three driving styles that modify the reward signal
via jerk, speed, and lane-change penalty weights:

| Style | Jerk Penalty | Speed Bonus | Lane Change Penalty | Behaviour |
|-------|-------------|-------------|---------------------|-----------|
| Chill | 2.0 | 0.5 | 2.0 | Smooth, unhurried, minimal lane changes |
| Standard | 1.0 | 1.0 | 1.0 | Balanced default profile |
| Hurry | 0.5 | 2.0 | 0.5 | Aggressive speed, tolerant of jerk and lane changes |

Style weights are defined in `configs/ppo.yaml` under `reward_profiles`.
Checkpoints are saved as `ppo_{town}_{style}_best.pt`.

## DriveNet Architecture

DriveNet is a 5-layer CNN with an MLP head:

- **Features**: 5 convolutional layers (24/36/48/64/64 channels, 5x5 and 3x3
  kernels) with BatchNorm and ReLU, followed by Flatten.
- **State input**: Speed (normalized), heading (sin/cos encoded) -- 3 dimensions.
- **Metadata embeddings** (optional): Learned embeddings for weather, town, road
  type, time of day, and traffic density -- 12 additional dimensions.
- **Head**: 4-layer MLP (input -> 256 -> 128 -> 64 -> 3) with ReLU and dropout,
  producing [steer, throttle, brake]. Steer uses tanh ([-1, 1]), throttle and
  brake use sigmoid ([0, 1]).

## End-to-End Run Instructions

### Step 1: Data Collection (NB01) -- ~6 hours, all 6 towns

NB01 handles CARLA restarts internally via `restart_carla_and_reconnect()`.
No manual intervention is needed between towns.

```bash
# NB01 launches CARLA itself -- do NOT start CARLA beforehand
jupyter notebook notebooks/01_data_collection.ipynb
# Run all cells. Output: data/{Town}/chunk_XXXX.npz (324 conditions, ~97k frames)
```

### Step 2: Behavior Cloning (NB02) -- ~30 min, no CARLA needed

```bash
# CARLA is not needed for this step
jupyter notebook notebooks/02_behavior_cloning.ipynb
# Run all cells. Output: models/BC_model_best.pt
```

### Step 3: PPO Fine-Tuning (NB03) -- ~2 hours per town per style, 6 towns

NB03 trains all three driving styles (chill, standard, hurry) for the
currently loaded town. Repeat for each of the 6 towns.

```bash
# For each town: start CARLA with that town loaded, run NB03, close CARLA
CARLA_0.9.16/CarlaUE4.exe -dx12 /Game/Carla/Maps/Town01
jupyter notebook notebooks/03_ppo_finetuning.ipynb
# Run all cells. Output: models/ppo_Town01_{chill,standard,hurry}_best.pt
# Close CARLA, restart with Town02/Town03/... and repeat
```

### Step 4: Evaluation (NB04) -- ~1 hour per town, 3 eval towns

```bash
# Run one town per CARLA session. Restart between towns.
CARLA_0.9.16/CarlaUE4.exe -dx12 /Game/Carla/Maps/Town01
jupyter notebook notebooks/04_evaluation.ipynb
# Run all cells. Close CARLA, repeat for Town03 and Town05.
```

### Step 5: Causal Analysis (NB05) -- ~5 min, no CARLA needed

```bash
jupyter notebook notebooks/05_causal_analysis.ipynb
# Run all cells. Output: results/causal_results.json + plots
```

## CARLA Launch Reference

Use `-dx12` on RTX 5080 Blackwell. Do not call `client.load_world()` at runtime.
Restart CARLA between towns instead.

```bash
# Option A: Use the repo launch script (headless-friendly, low quality viewport)
scripts/launch_carla.bat

# Option B: Launch manually with a specific town
CARLA_0.9.16/CarlaUE4.exe -dx12 /Game/Carla/Maps/Town03
```

## Startup Crash Diagnostics

Use the startup matrix runner to diagnose crashes that happen after loading a
town and before data collection begins.

```bash
scripts/launch_carla.bat

python scripts/diagnose_startup_matrix.py --town Town01 --repeat 3
# Optional: include Vulkan control profile for A/B comparison
python scripts/diagnose_startup_matrix.py --town Town01 --repeat 3 --include-vulkan
```

The diagnostic report is saved to `results/startup_diagnostics/` as JSON and
captures: launch command/RHI, TCP-open and RPC-ready timing, map load status,
sync mode and sensor probe outcomes, pass/fail stage per cycle.

For teardown-specific crash validation, run:

```bash
python test_crash_scenarios.py --scenario 13
python test_crash_scenarios.py --scenario 14
```
